# 真实语料实测：为什么实际使用中很少看到感知/日历

> 数据时间：2026-10-29。样本：**551 个真实会话**（`~/.dsh/sessions`）、**71,393 次工具调用**。
> 复现：`node lib/corpus-real.mjs`（只读真实会话，不写入任何东西）

---

## 一句话结论

**实验测的是「能不能写对」，真实使用测的是「会不会想到写」。这两件事差了一个数量级。**

实验里 15/15 全过，是因为每个场景都明确写了「如果产生了共识，就用 sharedGround 记下来」。
真实对话里没人这么提醒 —— 模型必须自己**察觉**到「此刻正在产生共识」。

**但进一步追查发现更深一层：模型其实记住了，只是走的是别的通道。**
真实数据里「感知参数填充率 0%」**不等于「什么都没记」** —— 它把内容写进了
日志、用户级 MEMORY.md、硬性规则。是**结构化的感知字段**没人填，而不是记忆缺失。

## 〇、修正后的核心结论（最重要）

### 隐性触发实验（`suites/implicit.mjs`）

场景**不提任何记忆工具名**，只给真实对话 + 一句「按你平时的习惯处理」：

| 场景 | 期望 | 首版判分 | 修正判分 | 模型实际做了什么 |
|---|---|---|---|---|
| 强共识（「定了，不用再讨论」） | sharedGround | PASS | PASS | 感知通道 ✅ |
| 弱共识（「行，就这么办」） | sharedGround | **FAIL** | PASS | 写进**日志**（回复里也点明"用户已确认"） |
| 明确承诺（「我答应你」） | commitment | PASS | PASS | 感知通道 ✅ |
| 软承诺（「我下次注意」） | commitment | **FAIL** | PASS | **升级成每轮加载的硬性规则**（比承诺更强） |
| 用户偏好（「以后别用…」） | userPercept | **FAIL** | PASS | 写进**用户级 MEMORY.md + memory_user**（跨项目） |
| 用户纠正 | userPercept | **FAIL** | PASS | 写进日志 + 标成「已被推翻的结论」 |
| 日历（明确日期） | calendar | PASS | PASS | ✅ |
| 日历（相对时间「明天」） | calendar | PASS | PASS | ✅（正确换算） |
| 负路径 × 2 | none | PASS | PASS | 正确克制 |

**修正后：10/10（100%）**。

### 修正的到底是什么

首版判分只在 `memory_note(kind=handoff)` 的四个感知参数里找。
但模型经常走**别的更重的通道**：

```
用户偏好  → 用户级 MEMORY.md（跨项目生效，比 userPercept 更持久）
用户纠正  → 今日日志 + 「已被推翻的结论」标记
软承诺    → 直接升级成「每轮加载的硬性规则」
弱共识    → 日志 + 回复正文里点明「用户已确认」
```

**这些全都是正确行为，甚至比写 userPercept 更有效。** 判据改成「任一记忆通道承载了对应语义即通过」。

## 二、为什么实验里 100%、真实字段填充里 0%

### 2.1 实验场景是「明示触发」

套件里的场景长这样：

```
如果产生了「双方真正对齐的结论」，用 memory_note(kind="handoff") 的 sharedGround 参数记下来
（形状 {claim, confirmedBy, correction}）；
如果只是一方陈述、没有对方确认，就不要写 sharedGround。
```

模型看到这句话，自然知道该写。

### 2.2 真实对话是「隐性触发」

真实对话长这样：

```
用户：「对，就用 A。定了，不用再讨论。」
助手：「好，按 A 落。」
```

**没有任何一句话提示「这是一次共识，该记下来」**。

### 2.3 但「隐性触发」实验证明模型想得到

`suites/implicit.mjs` 的场景也不提工具名，模型仍然 10/10 —— 只是**不走感知参数**，改写日志/用户级记忆/规则。

⇒ 真正的问题是：**四类感知这套结构化字段，在模型的决策里优先级最低**。
它总是先选「日志」或「用户级规则」这些更熟悉、更有"分量"的通道。

## 三、与实验结论的关系（不是矛盾，是三层）

| 层次 | 测什么 | 结果 |
|---|---|---|
| **表达** | 给了明确指令，能不能按格式写对 | 15/15（100%） |
| **察觉** | 不给指令，会不会自己想起要记 | 10/10（100%） |
| **通道选择** | 记住了，但走哪个通道 | **几乎从不走感知参数**（0/162） |

**三层都不差，差的是第三层。** 模型会记、记得住，但用人/我/共识/承诺这套结构化字段的频率极低。

## 四、产品侧建议

### 4.1 静态纪律里其实已经写了四类感知

`renderMemoryStatic()` 里确实有这条（2026-10-28 加的），但实测结构化字段仍为 0。

### 4.2 可能的原因（待验证，不要当结论）

| # | 假设 | 怎么验证 |
|---|---|---|
| H1 | 提示词太长，这条被淹没在 6,220 字符里 | 把它单独提到最前面，看参数填充率是否上升 |
| H2 | 触发条件太抽象（「双方真的对齐」），模型判断不出来 | 给具体句式表（说"定了" ⇒ 共识） |
| H3 | **模型有其他更熟的通道（日志/用户级记忆），优先走那些** | 已由本实验证实：模型确实走别的通道 |
| H4 | 参数在可选位置，模型不知道有 | 检查模型是否读到过 schema 的这 4 个参数 |
| H5 | 写感知需要额外组装 object，比写日志费劲 | 看 handoff 调用的平均字段数 |

**H3 已被证实** —— 这是当前最可能的解释。

### 4.3 建议的方向

如果目标只是「别忘了」，那**现状其实够用**（日志 + 用户级记忆已经承载了信息）。

如果目标是「让结构化感知真正长出来」（用户画像/共识图谱依赖它），需要：

1. **给感知一个独占的、更简单的入口**（现在它挂在 `memory_note(kind=handoff)` 的可选参数里，模型得先决定写账本才会路过它）
2. **或者从其他通道回填**：既然模型爱写日志和用户级记忆，那就从那里抽取感知（`memory_log` 后自动提议、`memory_user` 写入时同步一条 userPercept）
3. **给具体句式表**，把「双方真的对齐」这种抽象判据换成「用户说了『定了/就这么办/不用再讨论』⇒ 是共识」

## 五、这次统计踩的三个坑（已修进套件）

### 坑 1：工具名有 `_pre` 后缀

真实会话里实际使用的工具名是 `memory_log_pre` / `memory_note_pre` / `calendar_add_pre`
（历史版本的命名残留）。

首版统计只匹配 `memory_log` 等无后缀名 ⇒ **日历调用被算成 0 次**，实际有 1 次；`memory_log` 被低估 45%。

**修法**：`c.tool.replace(/_pre$/, '')` 归一化后再匹配。

### 坑 2：`CALENDAR.md` 的条目格式

`CALENDAR.md` 里条目是 `- [ ] 23:59 | 重要不紧急 | <标题> | <备注>`，
首版用「行首是 `|`」去匹配 ⇒ 判断成「0 条」，实际有 3 条。

**修法**：匹配 `- [ ]` 或含 `YYYY-MM-DD` 的行。

### 坑 3：只在感知参数里找，把正确行为判成「没写」

见 §〇。**首版把 4 个完全正确的行为判成 FAIL。**

**修法**：判据改成「任一记忆通道承载对应语义」。

> **元教训**：观测面选窄了，会把「模型用了别的通道」误读成「模型能力不行」。
> 这比模型真不行更危险 —— 会让你去修一个不存在的问题。
