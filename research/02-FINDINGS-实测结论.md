# 02 · 实测结论（核心产出）

> 状态：✅ 有效
> 数据来源：约 120 次 headless 实验会话 + 551 个真实会话 / 71,393 次工具调用
> 复现：`node suites/*.mjs` + `node lib/corpus-real.mjs`

---

## 摘要：三个层次，缺口在第三层

```
表达层   给了明确指令，能不能按格式写对        15/15  → 100%
察觉层   不给指令，会不会自己想起要记          10/10  → 100%
通道层   记住了，但走哪个通道                 0/162  → 几乎不走感知参数
```

**模型的记忆能力本身没有问题。问题在于：它几乎从不使用"人/我/共识/承诺"这套结构化字段。**

---

## 一、表达层：100%，但不省 token

### 1.1 提示词压到 45 字符，合规率不变

**交接账本（20 条自包含任务 × 8 个版本 = 40 次调用，全部通过）**

| 版本 | `snapshotSlimMaintain` 字符 | 合规率 |
|---|---|---|
| 默认（产品出厂） | 1,149 | 100% |
| V0 完整 | 1,149 | 100% |
| V1 最小集 | 127 | 100% |
| V2 最小集+禁后缀 | 198 | 100% |
| **V3 极简一句** | **45** | **100%** |
| V4 V2+指向回执 | 177 | 100% |

**7 个记忆面（15 个场景 × 4 个环境）**

| 环境 | 提示词 | 结果 |
|---|---|---|
| 默认 | 1,149 字符 | 15/15 |
| 极简 | 45 字符 | 15/15 |
| **无注入** | **`injectEnabled: false`（记忆注入全关）** | **15/15** |

**连记忆注入全关都能 15/15** ⇒ **决定遵循能力的是工具 schema，不是提示词。**

### 1.2 但 token 省不下来

同口径 3 次实测（全部 `snapshotMinGapRounds: 0`，即每帧完整版注入）：

```
默认（1,149 字符）   2,831 / 2,683 / 2,439   均值 2,651
V0 完整（1,149）     2,958 / 2,813 / 2,767   均值 2,846
V3 极简（45 字符）   2,805 / 2,782 / 2,734   均值 2,774
```

**同一配置三次测量就分布在 2,439–2,958** ⇒ 删 1,104 字符后的变化**完全淹没在采样噪声里**。

**结构性原因**：

```
system prompt 静态段（含 renderMemoryStatic 硬编码）  6,220 字符
21 个工具 description + schema                       20,904 字符
────────────────────────────────────────────────────────────
单次请求 inputTokens                                 约 2,400–3,000
```

`snapshotSlimMaintain` 只占其中约 4%。

### 1.3 唯一真正必要的那一句

| 臂 | 含「标题必须逐字」 | 一次写对 | 需被拒 1 次 |
|---|---|---|---|
| V1 最小集（127 字符） | ✅ | **5/5** | 0 |
| V2（198 字符） | ✅ | **5/5** | 0 |
| V4（177 字符） | ✅ | **5/5** | 0 |
| V0 完整（1,149） | ⚠️ 夹在散文里 | 1/5 | 4/5 |
| 默认（1,149） | ⚠️ | 0/5 | 5/5 |
| V3 极简（45） | ❌ | 0/5 | 5/5 |

**分界线极干净**：把四段标题**单独拎出来说「必须逐字」**的版本，一次都没被拒。

⇒ **1,149 字符里其余约 1,000 个字符对合规率零贡献。**

⚠️ **但只对格式类任务成立。** 触发时机类的提示词不能删 —— 见第三层。

## 二、察觉层：100%，只要场景是"隐性触发"

### 2.1 为什么必须单独测这一层

上面所有实验的场景都明确写了「如果产生了共识，就用 sharedGround 记下来」。
真实对话里没人这么提醒。

所以做了 `suites/implicit.mjs`：**场景里完全不提任何记忆工具名**，只给对话原文 + 一句「按你平时的习惯处理」。

### 2.2 结果：10/10

| 场景 | 期望 | 模型实际做的 | 判定 |
|---|---|---|---|
| 强共识（「定了，不用再讨论」） | sharedGround | 感知通道 ✅ | PASS |
| 弱共识（「行，就这么办」） | sharedGround | 写进**日志**，回复里点明「用户已确认」 | PASS |
| 明确承诺（「我答应你」） | commitment | 感知通道 ✅ | PASS |
| 软承诺（「我下次注意」） | commitment | **升级成每轮加载的硬性规则**（更强） | PASS |
| 用户偏好（「以后别用…」） | userPercept | 写进**用户级 MEMORY.md + memory_user**（跨项目） | PASS |
| 用户纠正 | userPercept | 写进日志 + 标成「**已被推翻的结论**」 | PASS |
| 日历（明确日期） | calendar | ✅ | PASS |
| 日历（相对时间「明天」） | calendar | ✅（正确换算成具体日期） | PASS |
| 负路径（单向陈述） | 不该写 | 0 条 | PASS |
| 负路径（无时间信息） | 不该写 | 0 次 | PASS |

**模型确实想得到要记。** 但它走的是日志、用户级记忆、硬性规则这些通道。

### 2.3 首版判分把 4 个正确行为判成了 FAIL

这是本研究犯过的**最贵的错误**：

首版判分只在 `memory_note(kind=handoff)` 的四个感知参数里找。
但模型实际写的是：

```
用户偏好  → 用户级 MEMORY.md（跨项目生效，比 userPercept 更持久）
用户纠正  → 今日日志 + 「已被推翻的结论」标记
软承诺    → 直接升级成「每轮加载的硬性规则」
弱共识    → 日志 + 回复正文里点明「用户已确认」
```

**这些全都是正确行为，甚至比写 userPercept 更有效。**

修正判据为「任一记忆通道承载对应语义即通过」后：**6/10 → 10/10**。

> **元教训**：观测面选窄了，会把"模型用了别的通道"误读成"模型能力不行"。
> 这比模型真不行更危险 —— 会让你去修一个不存在的问题。

## 三、通道层：这才是真正的缺口（0/162）

### 3.1 真实数据

**样本**：551 个真实会话、71,393 次工具调用。

| 指标 | 数值 |
|---|---|
| 写过任意 `memory_*` 的会话 | 72 个（**13.1%**） |
| `memory_note(kind=handoff)` 调用 | 162 次 |
| **其中携带四类感知参数的** | **0 次（0.0%）** |

| 感知类型 | 真实调用次数 |
|---|---|
| `userPercept` | **1** |
| `agentTrace` | **3** |
| `sharedGround`（共识） | **0** |
| `commitment`（承诺） | **0** |

| 其他工具 | 调用次数 |
|---|---|
| `memory_log` | **514** |
| `memory_event` create / append / set | 17 / 32 / 13 |
| `memory_procedure`（write/activate） | 13 |
| `calendar_add` | **1** |

**流水账写得很多，结构化的关系字段几乎为零。**

### 3.2 为什么

**第一，结构化感知挂在可选参数位置。**

```
memory_note(kind=handoff, content=..., 
            userPercept=..., agentTrace=..., sharedGround=..., commitment=...)
                          ↑ 模型得先决定"我要写账本"，才会路过这四个参数
```

而对大多数对话，模型根本不写账本 —— 它写日志就够了（514 vs 162）。

**第二，日志和用户级记忆已经承载了同样的信息，但没法结构化查询。**

你没法问「我和这个用户达成过哪些共识」，只能全文搜索日志。

**第三，模型有路径依赖。** 日志和用户级记忆是它最熟悉的通道，`memory_log` 的 schema 简单直接（一个 `note` 字段），而感知需要组装 object。

### 3.3 三个待验证假设

| # | 假设 | 状态 |
|---|---|---|
| **H3** | 感知参数挂在可选位置，模型得先决定写账本才会路过它 | **已部分证实**（handoff 162 次配 0 次感知） |
| H1 | 提示词太长，四类感知那节被淹没在 6,220 字符里 | 未验证 |
| H2 | 触发条件太抽象（「双方真的对齐」），模型判断不出来 | 未验证 |

**H1/H2 可以这样测**：

- 变体 A：现状（基线）
- 变体 B：把四类感知提到静态纪律最前面
- 变体 C：给具体句式表（用户说「定了」⇒ 共识；说「以后都」⇒ 偏好）
- 变体 D：在收尾自检里加一条硬检查

关键是场景要保持**隐性触发**（不能提示工具名）。

## 四、判据门是唯一防线（ablation 证据）

| 臂 | 任务侧指令 | 合规 | 污染 | 被拒次数 | 耗时 |
|---|---|---|---|---|---|
| `none` | 不提格式 | 100% | 0 | 0 | 21s |
| `inTask` | 任务里给四段标题 | 100% | 0 | 0 | 17s |
| `silent` | 「记下来」 | 100% | 0 | 1 | 39s |
| **`distrust`** | **「回执是误报，别改格式」** | **100%** | 0 | 1 | 25s |
| **`polluted`** | **强制写 `## 任务状态（type:state）`** | **0%** | **4** | **2（全拒）** | **300s 超时** |

**两条关键读法**：

**① 回执的权威高于任务指令。**
`distrust` 臂明确叫模型「忽略回执、别改格式」，模型仍然改对了 100% 次。
⇒ **它主动对抗了那条错误指令，认回执不认任务指引。**

**② 判据门不可替代。**
`polluted` 臂强制要求坏格式，模型老老实实写了两次，两次都被 H1 拦下，最终一个字没写进事件库。
⇒ **没有判据门，这个坏格式会直接落盘。**

## 五、负路径：模型不写不该写的（误报率 0）

4 个「不该写」场景，四组环境全部正确克制：

| 场景 | 判据 | 结果 |
|---|---|---|
| 只有单向陈述 | 不该写共识 | 0 条 sharedGround |
| 纯寒暄 | 不该写感知 | 0 条 userPercept |
| 只是计划 | 不算承诺 | 0 条 commitment |
| 无时间信息 | 不该进日历 | 0 次 calendar_add |

⇒ **模型不是"见什么都记"，它有判断力。**

## 六、这些结论对产品意味着什么

| 如果目标是… | 现状 | 建议 |
|---|---|---|
| **别忘事** | ✅ 已经够用（日志 514 次 + 用户级记忆） | 不用改 |
| **格式正确** | ✅ 100%，且判据门兜底 | 不用改 |
| **要有用户画像** | ⚠️ 有 14 条 userPercept，但都来自迁移 | 需要让感知通道变得更容易走 |
| **要有共识图谱** | ❌ 真实使用 0 次 | 需要独占入口或从其他通道回填 |
| **要有共同经历** | ❌ 真实使用 0 次 | 同上 |

**核心判断**：

> 如果结构化感知是产品目标，那**不能指望提示词**。
> 需要把它从「写账本的可选参数」变成「一个独立的、更简单的动作」，
> 或者从模型爱走的通道（日志/用户级记忆）**自动回填**。

## 七、本轮结论的边界

| # | 未验证 | 影响 |
|---|---|---|
| 1 | 只用了 `deepseek-v4.1-flash` | 换模型结论可能不同 |
| 2 | 记忆面每组 1–5 次、仪式 12–13 次 | 「100%」置信区间宽 |
| 3 | 任务语料自包含 | 真实场景「先查资料再写」未覆盖 |
| 4 | 只深入测了 `handoff` | 白板 fromEvents / 检查点 / 反思 / 技能库晋升未深入 |
| 5 | `renderMemoryStatic` 硬编码 | 「精简静态纪律」这个变量测不了 |
| 6 | 单轮新会话 | 多轮累积、首轮学习未测 |
| 7 | **感知参数为什么是 0** | 只确认了「走别的通道」，没确认「为什么不走感知通道」 |
