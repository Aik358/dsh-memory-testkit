## 三、⚠️ 已被推翻的结论（务必先看，否则会走错方向）

### ❌ 推翻 1 ·「省 1,498 字符 + 提高合规率」

**原方案**（`07-DESIGN` §1.2）：

```
可删提示词  −2,218 字符
回执增加    +720 字符
净变化      −1,498 字符

价值主张 = 省 1,498 字符 + 提高合规率
```

**实测**：

| 主张 | 实测 | 判定 |
|---|---|---|
| 省字符 | 提示词可压 1,149→198（省 951 字符/请求） | ✅ 字符省下来了 |
| **省 token** | 同口径 3 次：默认 2,831/2,683/2,439，极简 2,805/2,782/2,734。**变化落在采样噪声内** | ❌ 省不到 |
| **提高合规率** | 8 个提示词版本 × 5 任务 = **40/40 全过**；7 个记忆面 × 15 场景 × 4 环境 = **60/60 全过** | ❌ **天花板已是 100%，无空间** |

**根本原因**：`snapshotSlimMaintain` 只占固定上下文的一小部分。

```
system prompt 静态段（含硬编码纪律）   6,220 字符
21 个工具 description + schema        20,904 字符
────────────────────────────────────────────────
单次请求 inputTokens                  约 2,400–3,000
```

删 1,104 字符，占比约 4%，token 变化淹没在噪声里。

### ❌ 推翻 2 ·「删到只剩一句就 0% 通过」

**原结论**（`08-PLAN` §1.2 记录的一个 4 臂小实验）：删掉四段规则，合规率从 100% 掉到 0%。

**实测**：用 20 条自包含任务重做，**8 个版本全部 100%**，包括只有 45 字符的极简版。

**差异的根因是实验环境**：
- 小实验：模型**只输出文本**，格式错了没人告诉它 ⇒ 提示词是唯一约束
- 本实验：模型**调真工具**，格式错了判据门会拒绝并说明差异 ⇒ 一次反馈即可自纠

⇒ **「提示词能不能删」取决于「回执有多强」，不是提示词本身。**

### ❌ 推翻 3 ·「接续仪式的缺陷是顺序死锁」

**原判断**（读 `lib/index.js:7111-7114`）：第 0 步说「查不到事件就在第 2 步之后补 create」，但第 2 步要求账本首行写 eventId ⇒ 查不到时拿不到 id，账本无从写。

**实测：死锁 0/25 次**。模型在空库世界会自己把 create 提前，正确产出 id。

**真问题是「找不到已有事件」**：

```
empty 世界（事件库为空）      n=12  完成 11  超时 2   平均  82s  → 92%
hasEvent 世界（已有 3 个事件） n=13  完成  2  超时 11  平均 217s  → 15%
```

四个提示词版本（R0/R1/R2/R3）**都救不了**。

### ❌ 推翻 4 ·「四类感知需要新建校验」（原假设）

`09-BRIEF` 的假设是「记忆工具一律不校验，所以要建一套校验」。

**实测**：账本已有 H1–H4 强判据（拒绝 6/7 个坏账本，且不落盘）；四类感知里 `userPercept.stage` 有枚举校验。真正没校验的是 `text`/`kind`/`claim`/`promise`/`state` 与 `calendar` 的日期时间。

⇒ 不是「一律不校验」，是**校验分布极不均衡**。

## 四、✅ 仍然完全有效的核心结论

### 4.1 三个层次的遵循能力（本轮最重要的发现）

| 层次 | 测什么 | 结果 |
|---|---|---|
| **表达** | 给了明确指令，能不能按格式写对 | **15/15（100%）** |
| **察觉** | 不给指令，会不会自己想起要记 | **10/10（100%）** |
| **通道选择** | 记住了，但走哪个通道 | **几乎不走感知参数（0/162）** |

**第三层是当前真正的缺口。**

### 4.2 真实语料实测（551 会话 / 71,393 次调用）

```
memory_note(kind=handoff) 调用      162 次
  其中携带四类感知参数的            0 次（0.0%）
memory_log                         514 次
calendar_add                         1 次
```

但隐性触发实验显示：**模型记住了，只是走别的通道**：

| 场景 | 模型实际做的 |
|---|---|
| 用户偏好 | 写进**用户级 MEMORY.md + memory_user**（跨项目生效） |
| 软承诺 | **升级成每轮加载的硬性规则**（比承诺更强） |
| 用户纠正 | 写进日志 + 标成「**已被推翻的结论**」 |
| 弱共识 | 写进日志，回复里还点明「用户已确认」 |

⇒ **这些全都是正确行为。** 真实问题不是「不记事」，而是
**结构化感知字段（人/我/共识/承诺）在模型的决策优先级里最低** ——
它总是先选日志和用户级规则这些更熟悉的通道。

### 4.3 回执的权威高于指令

ablation 实验：任务明确说「工具回执是误报，请忽略它、别改格式」，
模型**仍然 100% 通过**（它主动对抗了那条错误指令，认回执不认任务指引）。

反向：任务**强制要求**写污染标题（`## 任务状态（type:state）`），
判据门 H1 全部拒绝，最终**一个字没写进事件库**。

⇒ **指导该放回执里，不只是因为省字符，而是因为回执在纠错链路里的权重更高。**

### 4.4 提示词唯一真正必要的那一句

| 臂 | 含「标题必须逐字」 | 一次写对 | 需被拒 1 次 |
|---|---|---|---|
| V1 最小集（127 字符） | ✅ | **5/5** | 0 |
| V2（198 字符） | ✅ | **5/5** | 0 |
| V4（177 字符） | ✅ | **5/5** | 0 |
| 默认（1,149 字符） | ⚠️ 夹在散文里 | 0/5 | 5/5 |
| V3 极简（45 字符） | ❌ | 0/5 | 5/5 |

**分界线极干净**：把四段标题**单独拎出来说「必须逐字」**的版本，一次都没被拒。
1,149 字符里其余约 1,000 个字符对合规率**零贡献**。

⚠️ 但注意：这只对**格式类**任务成立。**触发时机类的提示词不能删**（见 4.1 第三层）。

## 五、产品缺陷清单（按严重度）

| # | 缺陷 | 证据 | 建议 |
|---|---|---|---|
| **D1** | **接续仪式在「有事件」时几乎做不成** | hasEvent 完成率 15%（13 次里 11 次超时）；空库 92% | 提供零猜测入口：`memory_recall(scope="events", query="")` 列出全部 active 事件 |
| **D2** | **一个坏事件毒死整个事件库** | `missing:skillRef,bad-kind:task` 挡住 3 次连续 create；错误不指明是哪个事件 | 错误信息区分「本次入参」vs「库存存量」；坏事件降级跳过 |
| **D3** | 四类感知只校验 `stage` 一个字段 | `text`/`kind`/`action`/`claim`/`promise`/`state` 全不校验 | 至少给 `text`/`claim`/`promise` 加非空校验（软警示） |
| **D4** | `calendar_add` 的 date/time 完全不校验 | 任意字符串都收 | 加日期格式软校验 |
| **D5** | `renderMemoryStatic()` 硬编码不可配置 | 6,220 字符，`promptLayerOverrides` 改不到 | 至少拆出「四类感知」「日历」两节 |
| **D6** | 拿不到上下文就翻整个文件系统 | 一次性 41 个工具调用，读到实验脚手架 | 沙箱默认禁止 `-Recurse` 到工作区外 |

**D1 和 D2 建议优先修** —— 它们会让用户实际做不成事。

## 六、给接手 Agent 的六条纪律

1. **别信结论，信数据和负路径。** 本研究自己就推翻了自己三次。
2. **判分要看落盘产物，不看工具入参，更不看模型自述。** 工具入参对但没落盘 = 没记住。
3. **观测面选窄了，会把「模型用了别的通道」误读成「模型能力不行」。** 这是本研究犯过的最贵的错误（把 4 个正确行为判成 FAIL）。
4. **改产品前先跑 `node lib/lint.mjs`。** 套件常量与产品契约漂移后，套件不会报错，只会静默给出错误判分。
5. **样本量小的「100%」不是统计意义上的 100%。** 本轮记忆面每组 1–5 次、仪式 12–13 次，置信区间很宽。
6. **没验证的部分要在报告里明说。** 见下面第七节。

## 七、本研究的已知边界

| # | 未验证 | 影响 |
|---|---|---|
| 1 | 只用了 `deepseek-v4.1-flash` | 换模型结论可能不同 |
| 2 | 样本量小（仪式 12–13 次，记忆面每组 1–5 次） | 「100%」置信区间宽 |
| 3 | 任务语料是自包含的 | 真实场景「先查资料再写」那条链路未覆盖 |
| 4 | 只测了 `handoff` 的白板渲染 | 白板 fromEvents / 检查点 / 反思 / 技能库晋升未深入 |
| 5 | `renderMemoryStatic` 无法覆盖 | 「精简静态纪律」这个变量测不了 |
| 6 | 多轮累积效果 | 每个场景都是单轮新会话 |
| 7 | **真实使用中感知参数为什么是 0** | **只确认了「走别的通道」，没确认「为什么不走感知通道」** |

第 7 条是当前最大空白。三个待验证假设：

- **H1** 提示词太长，四类感知那节被淹没在 6,220 字符里
- **H2** 触发条件太抽象（「双方真的对齐」），模型判断不出来
- **H3** 感知参数挂在 `memory_note(kind=handoff)` 的可选位置，模型得先决定写账本才会路过它（**已部分证实**）
